## Bug reproduced and repaired in 1.5.5

Previously, saving a planner suggestion did not reduce its remaining task workload or daily capacity; it could therefore be suggested repeatedly. Overdue tasks also used their past due date as the study-session date.

The planner now deducts saved/completed source-linked session hours, respects configured daily capacity separately for each date, schedules overdue work today, and revalidates a suggestion when it is clicked. It preserves all existing sessions, assignments, exams and data keys. Regression tests cover full/partial allocation, completed sessions, personal sessions, per-date limits, and overdue dates. Browser and integration checks confirm that a saved, fully allocated task is not suggested again.

Changed application files: `js/app.js`, `index.html`, `service-worker.js`. Added regression coverage: `tests/planner-regression.test.mjs`. Release notes: `README.md`. This report is `AUDIT-2026-11-15.md`. Static cache advances to version 16; app version is 1.5.5. No database/schema/storage migrations or grading-formula changes.

## Verification limits

This is a bounded audit, not a guarantee of every possible input or device. Physical iPhone/Android devices and their real install prompts were not available. Browser mobile tests use viewport resizing, not an actual iOS WebKit engine. Real sign-up, email delivery/confirmation, password/account deletion and cross-device authenticated writes were not exercised against production; account/save behavior was tested with mocks, alongside read-only live checks. Offline/cache behavior is covered by the existing service-worker test harness, not an actual installed-device offline run. No runtime-log scan from the Vercel account was performed. No further failures were found in the tested flows; a dedicated public contact email remains unconfigured by design.
